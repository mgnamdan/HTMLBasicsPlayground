PART 1

Information: the HTML layer

What HTML is responsible for

A webpage begins as a document. HTML identifies the information and controls that belong in that document, then organizes them into a meaningful structure.

HTML defines what exists and how it is organized.

HTML can establish that a portfolio contains a heading, a summary, a holdings table, a policy note, and a form. CSS will later control their visual presentation. JavaScript will later update data, perform calculations, validate input, and respond to user actions.

The structure of a complete document

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Page title</title>
  </head>
  <body>
    <h1>Visible page content begins here</h1>
  </body>
</html>
<!doctype html>
Tells the browser to interpret the document as modern HTML.
<html>
Contains the entire HTML document.
<head>
Contains information about the document.
<body>
Contains the document content presented to the user.

Elements, tags, content, and attributes

<section data-state="active">Position content</section>
└──────┘ └─────────────────┘ └──────────────┘ └─────────┘
opening       attribute          content       closing
  tag                                             tag

The opening and closing tags establish the boundaries of the element. Content appears inside it. Attributes attach additional information or configuration to the element.

Some elements, including <meta>, <input>, and <hr>, do not wrap content and therefore do not use a closing tag.

HTML becomes a tree of objects

The browser parses the source and constructs a Document Object Model, usually shortened to DOM. 

document
└── html
    ├── head
    │   └── title
    └── body
        ├── header
        │   ├── h1
        │   └── p
        └── main
            └── section
                ├── h2
                └── table
Parent
An element that directly contains another element.
Child
An element directly contained by another element.
Sibling
Elements that share the same parent.
Descendant
An element nested anywhere inside another element.

Common elements used in this lab

Elements and their semantic purposes
Element Purpose
<header> Introduces a page or section.
<section> Groups content around a related topic.
<p> Represents a paragraph.
<ul> and <ol> Represent unordered and ordered lists.
<dl> Associates terms with descriptions or values.
<table> Organizes records with shared fields into rows and columns.
<form> Groups controls used to collect user input.
<details> Provides a native expandable disclosure.

PART 3

Exercises

Stage A: work inside the live demo

Complete these exercises in Panel A above. Render after every change and compare your source with the result.

Exercise 1 — Change existing content
  1. Change the position ID from LP-104 to LP-200.
  2. Change the pool name.
  3. Change the recorded profit/loss.
  4. Render and identify what changed without changing any tags.
Exercise 2 — Add an element

Add a paragraph beneath the main heading that identifies a fictional account owner. Then add a new item to the policy note's ordered list.

Exercise 3 — Add a table record

Add a third row to the balances table. Include an asset heading, quantity, and recorded value. Follow the structure of the existing rows.

Exercise 4 — Create and nest a section

Add a new section titled Fees and costs. Inside it, create an unordered list containing collected fees, uncollected fees, gas costs, and swap costs. Nest the two cost items under an Execution costs list item.

Exercise 5 — Modify attributes
  • Change the meter's value.
  • Remove open from <details>.
  • Remove disabled from the button.
  • Add data-status="watch" to the article.

Which attributes cause an immediate visible or native behavior change? Which simply store information for later use?

Exercise 6 — Observe browser error recovery

Save a working copy of the demo source. Remove one closing tag, render the document, and inspect the result. Restore the tag afterward.

Stage B: open and modify this webpage's source code

The live demo changes a document contained inside the page. The remaining exercises change the actual page. Open index.html in your code editor, save after each change, and refresh the browser.

Exercise 7 — Locate the page's major objects
  1. Find the page's top-level <header>, <main>, and <footer>.
  2. Find the three sections with IDs lesson, demo, and exercises.
  3. Identify the parent of those sections.
  4. Find the script element that connects demo.js.
Exercise 8 — Make a small page-level edit

Change the page's main heading and the text beneath it. Save index.html, refresh the browser, and confirm that you edited the actual page rather than the document inside the demo.

Exercise 9 — Extend the position register

Find the sample position register in Part 1 and add a third position. Preserve its heading cells, data cells, and column order.

Exercise 10 — Add a new page section
  1. Add a section immediately before the Summary section.
  2. Give it the ID reflection.
  3. Add a heading, one paragraph, and a list of three HTML concepts you learned.
  4. Add a Reflection anchor to the navigation at the top of the page.
  5. Save, refresh, and test the new navigation link.
Final extension — Add your own exercise to the lab

Add another <details> element to this exercise section. Give it a <summary> and instructions that require a fictional student to add or reorganize HTML elements.
